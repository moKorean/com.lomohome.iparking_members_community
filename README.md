# 아이파킹 방문차량 (Homey)

**아이파킹(iParking)을 사용하는 건물에 사는 사람이, 자기 집에 오는 방문 차량의 주차를
등록하기 위한 앱입니다.** 아이파킹 MEMBERS 웹사이트의 **방문 차량 관리** 기능을 Homey에서
쓸 수 있게 만든 것으로, 로그인해서 주차장명을 확인하고, 차량번호와 방문 예정일을 입력해
방문 차량을 등록하고, 등록 내역을 보고 취소할 수 있습니다.

아이파킹의 **공식 앱이 아닌, 비공식·커뮤니티 제작 앱**입니다. 공식 문서가 없는 웹사이트를
리버스 엔지니어링해서 만들었습니다 — 자세한 내용은 [`docs/RECON.md`](./docs/RECON.md)를
참고하세요.

> English README: [`README.en.md`](./README.en.md)

## ⚠️ 개인 용도 전용 — 그래서 앱스토어에 올리지 않습니다

**이 앱은 만든 사람이 자기 집 방문객 주차를 등록하려고 만든, 개인 용도 전용 앱입니다.**
쓰려면 아이파킹 MEMBERS에 가입된 건물의 **본인 세대 계정**이 있어야 합니다. 계정 하나는
한 세대에 묶여 있고, 그 세대에 오는 방문 차량만 등록할 수 있습니다.

그래서 **Homey 앱스토어에 올리지 않습니다.** `homey app install`로 직접 설치해서 씁니다.
이유는 순서대로 이렇습니다.

1. **애초에 개인 용도 앱입니다.** 배포해서 여러 사람이 쓸 것을 전제로 만들지 않았습니다.
   쓸 수 있는 사람은 아이파킹 가입 건물의 자기 세대 계정을 가진 사람뿐이라, 스토어에
   올려서 얻을 수 있는 사용자층이 사실상 없습니다.
2. 아이파킹의 **비공식·비공개 API**를 그대로 이용하고, 벤더의 암호화 키를 소스에 담고
   있습니다. 벤더가 이를 원하지 않을 수 있고, 스토어 심사에서 문제가 될 수 있습니다.
3. **실제 아파트 단지의 출입통제 시스템에 쓰기 작업을 합니다.** 넓게 배포할 성격의
   동작이 아닙니다.

전체 근거와, 자체 설치일 때 어떤 배포 절차가 적용되고 어떤 것이 적용되지 않는지는
[`docs/DISTRIBUTION.md`](./docs/DISTRIBUTION.md)에 정리해 두었습니다.

**쓰시는 분께.** 본인 계정으로, 본인 세대에 오는 방문 차량만 등록하세요. 남의 계정으로
로그인하거나, 본인과 무관한 차량을 등록하는 용도로 쓰지 마세요. 등록은 실제 차단기 동작에
그대로 반영됩니다.

## 꼭 알아야 할 것 (disclosures)

- **비공식 클라이언트입니다.** 아이파킹의 공식 문서가 없는 내부 API를 그대로 이용합니다.
- **아이파킹 API 서버(`members.iparking.co.kr`)는 모든 HTTPS 요청을 평문 HTTP로
  되돌립니다(301 redirect).** 그래서 로그인 이후의 접근 토큰과 차량번호·방문일 데이터는
  **암호화되지 않은 상태로** 인터넷을 오갑니다. 이것은 **서버(벤더) 쪽의 동작**이고, 이
  클라이언트에서 고칠 방법이 없습니다.
- 반대로 **비밀번호는** 검증된 TLS로 오는 로그인 서버(`oauth.parkingcloud.co.kr`)를 통해
  안전하게 전송됩니다 — 위 항목은 과장이 아니라 정확한 설명입니다: 한쪽 서버는 보호되고,
  다른 쪽은 그럴 수 없습니다.
- 요청 본문에 걸려 있는 "암호화"는 **모든 브라우저에 그대로 박혀 있는 고정 키를 쓰는
  벤더 측 난독화**이지, 기밀성을 위한 것이 아닙니다.
- 계정 자격증명(아이디/비밀번호)은 **사용자 본인의 Homey에** 저장됩니다.
- **방문 차량을 등록하면 실제 아파트 단지의 출입통제 시스템에 그대로 반영됩니다.**
  테스트 삼아 아무 값이나 등록하지 마세요.

## 기능

- **계정 로그인** — 앱 설정에서 아이파킹 MEMBERS 아이디/비밀번호로 로그인합니다.
- **주차장명 센서** — 계정에 연결된 주차장 이름을 기기 캐패빌리티로 보여줍니다.
- **방문차량 등록** — 앱 설정 화면(주 UI)에서 주차장을 고르고, 차량번호와 방문 예정일을
  입력해 등록합니다. 차량번호의 공백은 자동으로 제거되고, 입력란을 벗어나면(blur) 정리된
  번호가 그대로 보입니다. 방문 예정일의 "오늘"은 항상 **한국 표준시(KST) 기준**입니다 —
  Homey가 어느 시간대에 있든 동일합니다.
- **플로우(Flow) 액션** `register_visitor` — 자동화에서 방문 차량을 등록합니다.
- **등록 내역** — 앱 설정 화면에서 등록된 차량 목록을 확인하고, 각 항목을 취소할 수
  있습니다.
- **이미 등록된 차량 안내** — 같은 차량번호를 다시 등록하면 오류가 아니라 "이미 등록된
  차량"이라는 별도 결과로 안내합니다.
- **등록 결과 불확실 안내** — 등록 요청이 타임아웃 등으로 결과를 확인할 수 없는 경우,
  "성공/실패"로 단정하지 않고 아이파킹 웹사이트에서 직접 확인하도록 안내하며, **재시도를
  권하지 않습니다** — 재시도는 불확실했던 등록 하나를 실제 등록 두 건으로 만들 수 있는
  가장 위험한 동작이기 때문입니다.

## 설정

1. Homey에 앱을 설치합니다 (`homey app install`).
2. **앱 설정**을 열고 아이파킹 MEMBERS 계정 아이디/비밀번호로 로그인합니다.
3. 기기 추가 → **아이파킹 방문차량** → 계정에 연결된 주차장을 선택합니다.
4. 앱 설정 화면에서 차량번호와 방문 예정일을 입력해 등록하고, 등록 내역을 확인합니다.

## 빌드

Homey **Python 런타임** 앱(SDK 3)입니다. 런타임 의존성은 `app.json`의 `pythonPackages`에
선언된 `certifi`뿐입니다. 아이파킹 요청 본문의 AES-256 암복호화는 외부 패키지 없이 이
저장소에 벤더링되어 있습니다 (`iparking_lib/iparking/aes.py`) — 130줄 남짓한 완전히 명세된
알고리즘이고, 정확성은 외부에서 생성한 테스트 벡터로 고정해 두었습니다.

```sh
homey app build              # .homeycompose/* 를 app.json 으로 병합
homey app install            # 빌드 후 연결된 Homey 에 설치
homey app run                 # 개발 모드(실시간 로그) — 페어링/로그인 문제 진단용
homey app validate --level publish   # 매 변경마다 실행하는 위생 검증(제출 목적 아님)
uv run pytest -q              # 순수 클라이언트 로직 단위 테스트
```

스토어 이미지는 `docs/app-image.svg`(원본 벡터)를 `scripts/make_images.py`로 생성합니다.
