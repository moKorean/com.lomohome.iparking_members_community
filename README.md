# 아이파킹 방문차량 (Homey)

**아이파킹(iParking)을 사용하는 건물에 사는 사람이, 자기 집에 오는 방문 차량의 주차를
등록하기 위한 앱입니다.** 아이파킹 MEMBERS 웹사이트의 **방문 차량 관리** 기능을 Homey에서
쓸 수 있게 만든 것으로, 로그인한 뒤 차량번호와 방문 예정일을 입력해 방문 차량을 등록하고,
오늘 방문 예정인 차량이 몇 대인지 기기 화면에서 확인하고, 등록 내역을 보고 취소할 수 있습니다.

아이파킹의 **공식 앱이 아닌, 비공식·커뮤니티 제작 앱**입니다. 공식 문서가 없는 웹사이트를
리버스 엔지니어링해서 만들었습니다 — 자세한 내용은 [`docs/RECON.md`](./docs/RECON.md)를
참고하세요.

> English README: [`README.en.md`](./README.en.md)

## ⚠️ 개인 용도 전용 — 그래서 앱스토어에 올리지 않습니다

**이 앱은 만든 사람이 자기 집 방문객 주차를 등록하려고 만든, 개인 용도 전용 앱입니다.**
쓰려면 아이파킹 MEMBERS에 가입된 건물의 **본인 세대 계정**이 있어야 합니다. 계정 하나는
한 세대에 묶여 있고, 그 세대에 오는 방문 차량만 등록할 수 있습니다.

그래서 **Homey 앱스토어에 올리지 않습니다.** `homey app install`로 직접 설치해서 씁니다.
이유는 순서대로 이렇습니다.

1. **애초에 개인 용도 앱입니다.** 배포해서 여러 사람이 쓸 것을 전제로 만들지 않았습니다.
   쓸 수 있는 사람은 아이파킹 가입 건물의 자기 세대 계정을 가진 사람뿐이라, 스토어에
   올려서 얻을 수 있는 사용자층이 사실상 없습니다.
2. 아이파킹의 **비공식·비공개 API**를 그대로 이용하고, 벤더의 암호화 키를 소스에 담고
   있습니다. 벤더가 이를 원하지 않을 수 있고, 스토어 심사에서 문제가 될 수 있습니다.
3. **실제 아파트 단지의 출입통제 시스템에 쓰기 작업을 합니다.** 넓게 배포할 성격의
   동작이 아닙니다.

전체 근거와, 자체 설치일 때 어떤 배포 절차가 적용되고 어떤 것이 적용되지 않는지는
[`docs/DISTRIBUTION.md`](./docs/DISTRIBUTION.md)에 정리해 두었습니다.

**쓰시는 분께.** 본인 계정으로, 본인 세대에 오는 방문 차량만 등록하세요. 남의 계정으로
로그인하거나, 본인과 무관한 차량을 등록하는 용도로 쓰지 마세요. 등록은 실제 차단기 동작에
그대로 반영됩니다.

## 꼭 알아야 할 것 (disclosures)

- **비공식 클라이언트입니다.** 아이파킹의 공식 문서가 없는 내부 API를 그대로 이용합니다.
- **아이파킹 API 서버(`members.iparking.co.kr`)는 모든 HTTPS 요청을 평문 HTTP로
  되돌립니다(301 redirect).** 그래서 로그인 이후의 접근 토큰과 차량번호·방문일 데이터는
  **암호화되지 않은 상태로** 인터넷을 오갑니다. 이것은 **서버(벤더) 쪽의 동작**이고, 이
  클라이언트에서 고칠 방법이 없습니다.
- 반대로 **비밀번호는** 검증된 TLS로 오는 로그인 서버(`oauth.parkingcloud.co.kr`)를 통해
  안전하게 전송됩니다 — 위 항목은 과장이 아니라 정확한 설명입니다: 한쪽 서버는 보호되고,
  다른 쪽은 그럴 수 없습니다.
- 요청 본문에 걸려 있는 "암호화"는 **모든 브라우저에 그대로 박혀 있는 고정 키를 쓰는
  벤더 측 난독화**이지, 기밀성을 위한 것이 아닙니다.
- 계정 자격증명(아이디/비밀번호)은 **사용자 본인의 Homey에** 저장됩니다.
- **방문 차량을 등록하면 실제 아파트 단지의 출입통제 시스템에 그대로 반영됩니다.**
  테스트 삼아 아무 값이나 등록하지 마세요.

## 기능

- **계정 로그인** — 앱 설정에서 아이파킹 MEMBERS 아이디/비밀번호로 로그인합니다.
- **오늘 방문 예정 센서** — 이 주차장에 **오늘 방문 예정인 차량이 몇 대인지** 기기
  캐패빌리티로 보여줍니다 (`오늘 방문 예정 · 2대`). Insights(기록 그래프)를 지원합니다.
  1시간마다(±10%) 요청 1건으로 갱신되고, 이 앱에서 등록·취소하거나 등록 내역을 불러올 때는
  **추가 요청 없이** 즉시 반영되며, 자정(KST)이 지나면 새 하루의 숫자로 바뀝니다.
  **취소된 등록은 세지 않습니다** — 아이파킹에서 취소는 항목을 지우는 대신 상태만 `CANCEL`로
  바꾸므로, 취소분까지 세면 실제로 1대인 날이 6대로 보입니다.
- **방문차량 등록** — 앱 설정 화면(주 UI)에서 주차장을 고르고, 차량번호와 방문 예정일을
  입력해 등록합니다. 차량번호의 공백은 자동으로 제거되고, 입력란을 벗어나면(blur) 정리된
  번호가 그대로 보입니다. 방문 예정일의 "오늘"은 항상 **한국 표준시(KST) 기준**입니다 —
  Homey가 어느 시간대에 있든 동일합니다.
- **플로우(Flow) 액션 두 장** — `register_visitor`(방문 차량 등록 (날짜 지정))는 차량번호와
  선택 입력인 방문 예정일을 받고, `register_visitor_today`(방문 차량 등록 (오늘))는 차량번호만
  받아 항상 오늘(KST)로 등록합니다. 두 카드는 동일한 등록 경로를 씁니다 — 날짜를 어디서
  얻는지만 다릅니다.
  <br>날짜를 지정하는 카드는 **성공 알림에 해석된 날짜를 되돌려 보여줍니다**
  (`12가4567 · 2026-08-05 (수) 방문 등록`). Homey 가 날짜를 `dd-mm-yyyy` 로 주는지
  `mm-dd-yyyy` 로 주는지가 문서로 확정되지 않았고 두 형태는 **모양이 똑같아서**, 잘못 읽으면
  엉뚱한 날짜에 조용히 등록됩니다. 값으로 판별할 수 있는 경우(`25-12-2026` 처럼 앞자리가
  12 를 넘을 때)는 자동으로 맞추고, 판별이 불가능한 경우에도 알림의 날짜를 한 번 확인하면
  바로 드러납니다. 그래서 날짜를 지정해 처음 쓰실 때는 알림을 확인해 보시기를 권합니다.
- **자주 오는 차량 버튼 (최대 10대)** — 기기 설정에 **자주 오는 차량 이름 1~10**과
  **차량번호 1~10**, 모두 20칸의 입력란이 있습니다. 이름과 차량번호가 **둘 다** 채워지고
  차량번호 형식까지 맞는 칸마다 기기 화면에 `[엄마차 방문 등록]` 같은 버튼이 하나씩 생기고,
  누르면 그 차량이 **오늘(KST)** 날짜로 등록됩니다. 눌렀다 떼는 **푸시 버튼**입니다 — 스위치처럼
  켜진 상태로 남지 않고 몇 번이든 다시 누를 수 있습니다. Flow 카드와 **똑같은 등록 경로**를
  쓰기 때문에 재시도 없는 등록, "이미 등록된 차량" 안내, 결과 불확실 안내가 전부 동일하게
  동작합니다. 저장할 때 차량번호의 공백은 정리된 형태로 다시 기록되어 화면에 그대로 보입니다
  (`12가 3456` → `12가3456`). 한쪽만 채운 칸이나 형식이 틀린 칸은 버튼을 만들지 않고, 어느
  칸이 왜 빠졌는지 앱 로그에 남습니다.
- **등록 내역** — 앱 설정 화면에서 등록된 차량 목록을 **최근 날짜부터** 확인하고, 각 항목을
  취소할 수 있습니다. 취소는 **두 번 눌러야** 실행됩니다 — 한 번 누르면 버튼이 `정말 취소?`로
  바뀌고, 다시 누르면 취소됩니다(5초 안에 다시 누르지 않으면 원래대로 돌아갑니다). 실제 출입
  권한을 즉시 해제하는 동작이라 한 번의 오조작으로 실행되지 않게 한 것입니다.
- **이미 등록된 차량 안내** — 같은 차량번호를 다시 등록하면 오류가 아니라 "이미 등록된
  차량"이라는 별도 결과로 안내합니다.
- **등록 결과 불확실 안내** — 등록 요청이 타임아웃 등으로 결과를 확인할 수 없는 경우,
  "성공/실패"로 단정하지 않고 아이파킹 웹사이트에서 직접 확인하도록 안내하며, **재시도를
  권하지 않습니다** — 재시도는 불확실했던 등록 하나를 실제 등록 두 건으로 만들 수 있는
  가장 위험한 동작이기 때문입니다.

## 지원 범위

"지원"과 "실기기 검증"을 구분해 적었습니다. 이 앱은 문서가 없는 API 를 관찰해서 만든 것이라,
구현했다는 것과 실제 단지에서 동작을 확인했다는 것은 다른 이야기입니다.

| 항목 | 상태 |
| --- | --- |
| 로그인 · 오늘 방문 예정 대수 센서 (Insights 지원) | **실기기 검증** |
| 방문차량 등록 (설정 화면) | **실기기 검증** |
| 등록 내역 조회 · 취소 (두 번 누르기) | **실기기 검증** |
| 자주 오는 차량 버튼 (기기 설정 20칸 → 최대 10개 푸시 버튼) | **실기기 검증** |
| 방문차량 등록 (Flow 액션 2장) | 지원 — 날짜 인자의 형태는 위 설명 참고 |
| 다중 단지/다중 주차장 계정 | 지원 — 코드는 N개 단지 × M개 주차장을 처리하지만, 실계정이 1 × 1 이라 그 경우만 검증됐습니다 |
| 등록 수정 (`PUT /invitations`) | 미지원 — 엔드포인트는 확인했지만 실제로 호출해 보지 않았습니다 |
| 방문객 SMS 발송 | 미지원 — 위와 같음 |
| 대시보드 위젯 | 계획만 있음 |

검증 환경: Homey Pro (firmware 13 계열), Python 런타임 3.14, 아이파킹 MEMBERS 계정 1개
(단지 1곳 · 주차장 1곳).

## 설정

1. Homey에 앱을 설치합니다 (`homey app install`).
2. **앱 설정**을 열고 아이파킹 MEMBERS 계정 아이디/비밀번호로 로그인합니다.
3. 기기 추가 → **아이파킹 방문차량** → 계정에 연결된 주차장을 선택합니다.
4. 앱 설정 화면에서 차량번호와 방문 예정일을 입력해 등록하고, 등록 내역을 확인합니다.
5. (선택) 자주 오는 차량이 있으면 **기기 설정**에 이름과 차량번호를 짝으로 넣어 두세요.
   기기 화면에 버튼이 생겨서 한 번 누르면 오늘 날짜로 등록됩니다.

## 알려진 제약

앱의 문제가 아니라 상대 서버의 성질이지만, 쓰다 보면 마주치게 되는 것들입니다.

- **아이파킹 API 서버가 평문 HTTP 연결의 약 3분의 1을 끊습니다.** 실측했습니다 — 동일한 조회
  요청 20회 중 6회가 `ConnectionReset`이었고, 헤더나 실행 환경과 무관하게 무작위로 발생합니다.
  그래서 조회·로그인·취소는 **재시도**합니다(4회, 잔여 실패율 0.8%). **등록은 재시도하지
  않습니다** — 연결이 끊겼을 때 "요청이 안 갔는지" "갔는데 응답만 잃었는지" 구분할 수 없어서
  재시도하면 같은 차량이 두 번 등록될 수 있습니다. 대신 결과를 다시 조회해서 확인하고, 그래도
  확인되지 않으면 "불확실"로 알려 드립니다.
- **기기 화면(타일)에서 버튼을 눌렀을 때는 토스트가 뜨지 않습니다.** Homey SDK에 성공을 알리는
  토스트 API가 없어서(전체를 확인했습니다), 결과는 **타임라인 알림**으로 갑니다. 앱 설정 화면에서
  등록할 때는 화면 안에 토스트가 뜹니다.
- **등록 가능 기간은 오늘부터 80일 이내**입니다. 조회 기간이 최근 3개월로 제한되어 있는데 등록
  쪽에도 같은 제한이 걸리는지는 확인하지 않아서, 보수적으로 잡아 둔 값입니다.

## 빌드

Homey **Python 런타임** 앱(SDK 3)입니다. 런타임 의존성은 `app.json`의 `pythonPackages`에
선언된 `certifi`뿐입니다. 아이파킹 요청 본문의 AES-256 암복호화는 외부 패키지 없이 이
저장소에 벤더링되어 있습니다 (`iparking_lib/iparking/aes.py`) — 130줄 남짓한 완전히 명세된
알고리즘이고, 정확성은 외부에서 생성한 테스트 벡터로 고정해 두었습니다.

```sh
homey app build              # .homeycompose/* 를 app.json 으로 병합
homey app install            # 빌드 후 연결된 Homey 에 설치
homey app run                 # 개발 모드(실시간 로그) — 페어링/로그인 문제 진단용
homey app validate --level publish   # 매 변경마다 실행하는 위생 검증(제출 목적 아님)
uv run pytest -q              # 순수 클라이언트 로직 단위 테스트
```

스토어 이미지는 `docs/app-image.svg`(원본 벡터)를 `scripts/make_images.py`로 생성합니다.
